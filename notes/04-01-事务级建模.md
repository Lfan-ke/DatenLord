# 接口与事务级建模

> TLM, Transaction-Level Modeling - 事务级建模：
>
> TLM 的核心思想是用标准接口 + 标准连接器来组装系统，而不是手写每个模块之间的连接规则。这样可以大大提高代码的可读性和可维护性

## 标准接口模式

> 这些接口/函数都是BSV库中规定好的标准组件/通信原语
> > Get、Put、Client、Server、toGet、toPut、toGPServer、toGPClient、mkConnection
>
> 大型 BSV 设计中，模块间的通信接口常常被标准化为 Get 和 Put 以及标准的 C/S

### GET/PUT

```bluespec
// Get 接口：获取一个值
interface Get#(type t);
  // 按照握手理解行为就是：ready 才 fire
  method ActionValue#(t) get();  // 阻塞直到有值，然后取出
endinterface

// Put 接口：放入一个值
interface Put#(type t);
  method Action put(t x);        // 阻塞直到可以放入，然后放入
endinterface
```

**使用示例**：

```bluespec
// 产生数据的模块
module mkDataSource(Get#(Bit#(8)));
  Reg#(Bit#(8)) counter <- mkReg(0);

  method ActionValue#(Bit#(8)) get();
    counter <= counter + 1;
    return counter;
  endmethod
endmodule

// 消费数据的模块
module mkDataSink(Put#(Bit#(8)));
  method Action put(Bit#(8) x);
    $display("Received: %d", x);
  endmethod
endmodule
```

### CLIENT/SERVER

```bluespec
// Server 接口：接收请求，返回响应
interface Server#(type req_t, type rsp_t);
  interface Put#(req_t) request;   // 接收请求
  interface Get#(rsp_t) response;  // 返回响应
endinterface

// Client 接口：发起请求，接收响应
interface Client#(type req_t, type rsp_t);
  interface Get#(req_t) request;   // 发出请求
  interface Put#(rsp_t) response;  // 接收响应
endinterface
```

**使用示例**：

```bluespec
// 内存模块（Server）
module mkMemory(Server#(Req, Rsp));
  FIFO#(Req) reqFifo <- mkFIFO;
  FIFO#(Rsp) rspFifo <- mkFIFO;

  // 处理请求的规则
  rule rl_process;
    let req = reqFifo.first;
    reqFifo.deq;
    // 处理请求...
    rspFifo.enq(response);
  endrule

  interface Put request = toPut(reqFifo);
  interface Get response = toGet(rspFifo);
endmodule

// CPU 模块（Client）
module mkCPU(Client#(Req, Rsp));
  // CPU 发起内存请求
endmodule
```

## 接口转换函数

> 连接不同抽象层次设计的“桥梁”，使用他们进行接口转化后，可以方便的用统一、简洁的语法去连接复杂的模块
> > 需要：`import GetPut::*;` 以及 `import FIFO::*;` 按需 `import Vector::*;`/`import Clocks::*;`

### toGet/toPut

> 将 FIFO 转为标准接口 Get/Put
> > 因为很多模块只认识 Get/Put，不认识 FIFO。转换后就可以直接用 mkConnection 连接。

```bluespec
FIFO#(t) fifo <- mkFIFO;

// toGet: 把 fifo 变成 Get 接口 - 内部实现：first() + deq()
Get#(t) get_ifc = toGet(fifo);

// toPut: 把 fifo 变成 Put 接口 - 内部实现：enq()
Put#(t) put_ifc = toPut(fifo);
```

### toGPServer/toGPClient

> 将单独的 Get 和 Put 组合成 Server 或 Client，方便连接。

```bluespec
// 参数顺序固定：先「请求侧」后「响应侧」(两个 FIFO/ToPut/ToGet)
// Server：被动方——请求从 reqFifo 进(Put)，响应从 respFifo 出(Get)
Server#(t, t) server = toGPServer(reqFifo, respFifo);   // (请求 ToPut, 响应 ToGet)

// Client：主动方——请求从 reqFifo 出(Get)，响应从 respFifo 进(Put)
Client#(t, t) client = toGPClient(reqFifo, respFifo);   // (请求 ToGet, 响应 ToPut)
```
> 记忆：两者都是 `(请求, 响应)` 顺序。Server 的 request 是 `Put`(收)、response 是 `Get`(发)；Client 反过来。

## 基础接口连接

> `import Connectable::mkConnection;`

```bluespec
// 连接 生产者到消费者 - Get    到 Put
mkConnection(get_ifc, put_ifc);

// 连接 主动发起后接收 - Client 到 Server
mkConnection(client , server );

// 也支持 CS 部分连接 - 退化为 Get到Put
mkConnection(c.request, s.request);
```

实际上类似于`wrapper`了一个`rule`，来将第一个参数视为生产者，第二个参数视为消费者，连接，或者，按顺序视为C/S.

**类似于**：

```bluespec
// Connectable 类型类定义
typeclass Connectable#(type a, type b);
  module mkConnection#(a x, b y)(Empty);
endtypeclass

// 实例：Get -> Put
instance Connectable#(Get#(t), Put#(t));
  module mkConnection#(Get#(t) g, Put#(t) p)(Empty);
    rule rl_connect;
      let x <- g.get();   // 从 Get 取数据
      p.put(x);           // 往 Put 放数据
    endrule
  endmodule
endinstance
```

**更加简洁一点理解**：

```bluespec
// mkConnection(Get, Put) 内部等价于：
rule rl_auto_connect;
  let x <- get_ifc.get();  // 从生产者取
  put_ifc.put(x);          // 给消费者放
endrule

// mkConnection(Client, Server) 内部等价于：
// 1. client.request (Get) → server.request (Put)
// 2. server.response (Get) → client.response (Put)
```

## 高级连接模式

### 仲裁器

> Arbiter

```bluespec
// ============================================================
// 功能：多个 Client 共享一个 Server，轮询仲裁
// 场景：多核 CPU 共享内存、多 DMA 共享总线
// ============================================================

module mkArbiter#(
    Vector#(n, Client#(req_t, rsp_t)) clients,   // 多个 Client（n/req_t/rsp_t 由参数类型推断）
    Server#(req_t, rsp_t) server                 // 单个 Server
)(Empty);

    // 当前选中的 Client 索引（轮询指针）
    Reg#(Bit#(TLog#(n))) current <- mkReg(0);
    // 是否有正在处理中的请求
    Reg#(Bool) pending <- mkReg(False);

    // 请求转发：从选中 Client 取请求，发给 Server
    rule rl_send_request if (!pending);
        let req <- clients[current].request.get();
        server.request.put(req);
        pending <= True;
    endrule

    // 响应转发：从 Server 取响应，发回给同一个 Client
    rule rl_receive_response if (pending);
        let rsp <- server.response.get();
        clients[current].response.put(rsp);
        pending <= False;
        // 轮转到下一个 Client
        current <= (current == fromInteger(valueOf(n) - 1)) ? 0 : current + 1;
    endrule

endmodule

// 仲裁器使用示例
/*
    场景：2 个 CPU 共享同一块内存

    // 创建模块
    Vector#(2, Client#(MemReq, MemRsp)) cpus <- replicateM(mkCPU);
    Server#(MemReq, MemRsp) memory <- mkMemory;

    // 连接（一行代码完成多路仲裁）
    mkArbiter(cpus, memory);

    // 效果：CPU0 和 CPU1 轮流访问内存，不会冲突
*/
```

### 路由器

> Router

```bluespec
// ============================================================
// 功能：单个 Client 根据地址路由到多个 Server
// 场景：CPU 访问内存/外设、网络包路由
// ============================================================

module mkRouter#(
    Client#(req_t, rsp_t) client,                     // 单个 Client
    Vector#(n, Server#(req_t, rsp_t)) servers,        // 多个 Server
    function idx_t get_index(req_t req)               // 地址解码函数（类型由参数推断）
)(Empty) provisos (Bits#(idx_t, isz), PrimIndex#(idx_t, ii));  // idx_t 要可存储且可索引 Vector

    // 记录当前请求发给了哪个设备
    Reg#(idx_t) pending_device <- mkRegU;
    Reg#(Bool)  pending <- mkReg(False);

    // 请求路由：解码后发给对应 Server
    rule rl_route_request if (!pending);
        let req <- client.request.get();
        let idx = get_index(req);
        pending_device <= idx;
        servers[idx].request.put(req);
        pending <= True;
    endrule

    // 响应返回：从对应 Server 取响应，返回给 Client
    rule rl_route_response if (pending);
        let idx = pending_device;
        let rsp <- servers[idx].response.get();
        client.response.put(rsp);
        pending <= False;
    endrule

endmodule

// 路由器使用示例
/*
    场景：CPU 根据地址访问不同设备

    // 定义请求类型
    typedef struct {
        Bit#(32) addr;
        Bit#(64) data;
        Bool write;
    } MemReq;

    // 地址解码函数
    function Bit#(2) addr_to_device(MemReq req);
        if (req.addr[31:28] == 'hF)
            return 0;      // 0xF0000000+ → UART
        else if (req.addr[31:28] == 'hE)
            return 1;      // 0xE0000000+ → GPIO
        else
            return 2;      // 其他 → 内存
    endfunction

    // 创建模块
    Client#(MemReq, MemRsp) cpu <- mkCPU;
    Vector#(3, Server#(MemReq, MemRsp)) devices;
    devices[0] <- mkUART;
    devices[1] <- mkGPIO;
    devices[2] <- mkMemory;

    // 连接（一行代码完成地址路由）
    mkRouter(cpu, devices, addr_to_device);

    // 效果：CPU 访问 0xF0001000 → 自动发往 UART
    //       CPU 访问 0xE0002000 → 自动发往 GPIO
    //       CPU 访问 0x00003000 → 自动发往内存
*/
```

### 流水线

> Pipeline

```bluespec
// ============================================================
// 功能：串联多个 Server，形成流水线
// 场景：图像处理、协议栈处理、加密解密
// ============================================================

module mkPipeline#(
    Server#(t1, t2) stage1,    // 第一级
    Server#(t2, t3) stage2     // 第二级
)(
    Server#(t1, t3)            // 组合后的 Server（t1/t2/t3 由参数推断）
) provisos (Bits#(t2, sz2));   // 中间类型 t2 需可存储（作为 FIFO 元素）

    // 流水线寄存器（mkPipelineFIFO 在 SpecialFIFOs，需 import SpecialFIFOs::*）
    FIFO#(t2) pipe <- mkPipelineFIFO;

    // 连接：stage1 → pipe → stage2
    mkConnection(stage1.response, toPut(pipe));
    mkConnection(toGet(pipe), stage2.request);

    // 暴露接口
    interface Put request = stage1.request;
    interface Get response = stage2.response;

endmodule

// 三级流水线构建器
module mkPipeline3#(
    Server#(t1, t2) stage1,
    Server#(t2, t3) stage2,
    Server#(t3, t4) stage3
)(
    Server#(t1, t4)
) provisos (Bits#(t2, a), Bits#(t3, b));   // 两个中间类型都需可存储

    let s12 <- mkPipeline(stage1, stage2);
    let s123 <- mkPipeline(s12, stage3);
    return s123;

endmodule

// 流水线使用示例
/*
    场景：图像处理：去噪 → 增强 → 压缩

    // 定义图像类型
    typedef Bit#(1920) Image;  // 简化示例

    // 创建各个处理阶段
    Server#(Image, Image) denoise <- mkDenoiseModule;
    Server#(Image, Image) enhance <- mkEnhanceModule;
    Server#(Image, Image) compress <- mkCompressModule;

    // 方式1：逐级构建
    Server#(Image, Image) pipeline <- mkPipeline3(denoise, enhance, compress);

    // 方式2：分步构建
    let stage12 <- mkPipeline(denoise, enhance);
    let pipeline2 <- mkPipeline(stage12, compress);

    // 使用流水线
    // 输入 raw_image → denoise → enhance → compress → 输出 compressed_image
    // 同时处理多张图片：stage1 处理图1，stage2 处理图0，stage3 处理图-1
*/
```

### 广播器

> Broadcast

```bluespec
// ============================================================
// 功能：一个数据源同时发给多个消费者
// 场景：日志分发、事件通知、数据备份
// ============================================================

module mkBroadcast#(
    Get#(t) source,                     // 单一数据源（t/n 由参数推断）
    Vector#(n, Put#(t)) sinks           // 多个消费者
)(Empty);

    rule rl_broadcast;
        let x <- source.get();
        for (Integer i = 0; i < valueOf(n); i = i + 1)
            sinks[i].put(x);
    endrule

endmodule

// 带条件过滤的广播器
module mkFilteredBroadcast#(
    Get#(t) source,
    Vector#(n, Put#(t)) sinks,
    function Bool filter(t x, Integer idx)
)(Empty);

    rule rl_broadcast;
        let x <- source.get();
        for (Integer i = 0; i < valueOf(n); i = i + 1)
            if (filter(x, i))
                sinks[i].put(x);
    endrule

endmodule

// 广播器使用示例
/*
    场景：系统日志同时输出到控制台、文件、网络

    // 创建日志源
    Get#(String) logger <- mkLogger;

    // 创建三个消费者
    Put#(String) console <- mkConsole;
    Put#(String) file <- mkFileWriter("log.txt");
    Put#(String) network <- mkUDPClient("192.168.1.100", 8888);

    // 创建消费者数组
    Vector#(3, Put#(String)) sinks;
    sinks[0] = console;
    sinks[1] = file;
    sinks[2] = network;

    // 广播日志（一行代码）
    mkBroadcast(logger, sinks);

    // 效果：每产生一条日志，自动发到控制台、文件、网络
    // console 显示 "[INFO] ..."
    // file 写入 "[INFO] ..."
    // network 发送 "[INFO] ..."

    // 带过滤的广播：只把错误日志发网络
    function Bool filter(String log, Integer idx);
        return (idx != 2) || log.contains("ERROR");
    endfunction
    mkFilteredBroadcast(logger, sinks, filter);
*/
```

### 归结器

> Reducer

#### 轮询归结器 示例

```bluespec
// ============================================================
// 功能：多个数据源轮询合并到一个消费者
// 场景：多路传感器数据采集、多通道合并
// ============================================================

module mkRoundRobinReducer#(
    Vector#(n, Get#(t)) sources,    // 多个数据源（t/n 由参数推断）
    Put#(t) sink                     // 单一消费者
)(Empty);

    Reg#(Bit#(TLog#(n))) current <- mkReg(0);

    rule rl_reduce;
        let x <- sources[current].get();
        sink.put(x);
        current <= (current == fromInteger(valueOf(n) - 1)) ? 0 : current + 1;
    endrule

endmodule

// 轮询归结器使用示例
/*
    场景：8 个温度传感器轮询采集

    // 创建传感器数组
    Vector#(8, Get#(Int)) sensors <- replicateM(mkTemperatureSensor);

    // 创建数据处理模块
    Put#(Int) processor <- mkDataProcessor;

    // 轮询合并（一行代码）
    mkRoundRobinReducer(sensors, processor);

    // 效果：依次采集 sensor0 → sensor1 → ... → sensor7 → sensor0 ...
    // 处理顺序：temp0, temp1, temp2, ... 循环
*/
```

#### 优先级归结器 示例

```bluespec
// ============================================================
// 功能：多个数据源按优先级合并（索引越小优先级越高）
// 场景：中断处理、QoS 调度
// ============================================================

// 带就绪检测的 Get 接口
interface PriorityGet#(type t);
    method ActionValue#(t) get();
    method Bool can_get();      // 是否有数据可取
endinterface

module mkPriorityReducer#(
    Vector#(n, PriorityGet#(t)) sources,    // 多个带优先级检测的源（t/n 由参数推断）
    Put#(t) sink                             // 单一消费者
)(Empty);

    // 找到第一个有数据的源（索引最小 = 优先级最高）
    // 注意：BSV 禁止 for 内提前 return，用累加器；从高到低遍历，低索引最后覆盖
    function Maybe#(Bit#(TLog#(n))) find_first_ready(Vector#(n, PriorityGet#(t)) srcs);
        Maybe#(Bit#(TLog#(n))) res = tagged Invalid;
        for (Integer i = valueOf(n) - 1; i >= 0; i = i - 1)
            if (srcs[i].can_get())
                res = tagged Valid fromInteger(i);
        return res;
    endfunction

    rule rl_reduce;
        case (find_first_ready(sources)) matches
            tagged Valid .idx: action          // 多语句分支须用 action...endaction 包裹
                let x <- sources[idx].get();
                sink.put(x);
            endaction
            tagged Invalid: noAction;    // 所有源都空，等待
        endcase
    endrule

endmodule

// 优先级归结器使用示例
/*
    场景：中断控制器，高优先级中断优先处理

    // 中断源 0（最高优先级）：定时器
    // 中断源 1：DMA 完成
    // 中断源 2：UART 接收

    // 假设中断源实现了 PriorityGet 接口
    Vector#(3, PriorityGet#(Int)) interrupts;
    interrupts[0] <- mkTimerInterrupt;
    interrupts[1] <- mkDMAInterrupt;
    interrupts[2] <- mkUARTInterrupt;

    // 创建中断处理器
    Put#(Int) handler <- mkInterruptHandler;

    // 优先级合并（一行代码）
    mkPriorityReducer(interrupts, handler);

    // 效果：同时有多个中断时，先处理索引小的
    // timer > DMA > UART
*/
```

#### 归并归结器 示例

```bluespec
// ============================================================
// 功能：多个有序数据源归并输出（类似归并排序）
// 场景：多路有序数据合并、排序器输出
// ============================================================

module mkMergeReducer#(
    Vector#(n, Get#(t)) sources,           // 多个有序数据源（t/n 由参数推断）
    Put#(t) sink,                           // 单一消费者
    function Bool less_than(t a, t b)       // 比较函数
)(Empty) provisos (Bits#(t, sz));   // t 需可存储（Vector of Reg#(Maybe#(t))）

    // 存储每个源的当前值（如果有）
    Vector#(n, Reg#(Maybe#(t))) buffers <- replicateM(mkReg(tagged Invalid));

    // 填充空缓冲区（循环内 rule：bsc 自动按索引生成 rl_fill_0/1/…，无需 SV 的 ## 拼名）
    for (Integer i = 0; i < valueOf(n); i = i + 1)
        rule rl_fill if (!isValid(buffers[i]));
            let x <- sources[i].get();
            buffers[i] <= tagged Valid x;
        endrule

    // 找出最小的有效值
    rule rl_output;
        function Maybe#(Bit#(TLog#(n))) find_min();
            Maybe#(Bit#(TLog#(n))) min_idx = tagged Invalid;
            for (Integer i = 0; i < valueOf(n); i = i + 1)
                if (isValid(buffers[i]))
                    if (!isValid(min_idx) ||
                        less_than(validValue(buffers[i]),
                                  validValue(buffers[validValue(min_idx)])))
                        min_idx = tagged Valid fromInteger(i);
            return min_idx;
        endfunction

        case (find_min()) matches
            tagged Valid .idx: action          // 多语句分支须 action...endaction
                let x = validValue(buffers[idx]);
                sink.put(x);
                buffers[idx] <= tagged Invalid;
            endaction
            tagged Invalid: noAction;
        endcase
    endrule

endmodule

// 归并归结器使用示例
/*
    场景：3 个有序数据源归并输出

    // 假设 source0: [1, 4, 7, ...]
    // source1: [2, 5, 8, ...]
    // source2: [3, 6, 9, ...]

    Vector#(3, Get#(Int)) sources;
    sources[0] <- mkSortedSource0;
    sources[1] <- mkSortedSource1;
    sources[2] <- mkSortedSource2;

    Put#(Int) sink <- mkSink;

    // 归并合并
    mkMergeReducer(sources, sink, less_than);

    // 效果：输出为 [1, 2, 3, 4, 5, 6, 7, 8, 9, ...]
    // 保持了全局有序
*/
```

#### 组合归结器 示例

```bluespec
// ============================================================
// 功能：从多个源各取一个值，组合成一个值输出
// 场景：求和、求最大值/最小值、向量点积
// ============================================================

module mkCombineReducer#(
    Vector#(n, Get#(t)) sources,        // 多个数据源（t/n 由参数推断）
    Put#(t) sink,                        // 单一消费者
    function t combine(t a, t b)         // 组合函数
)(Empty) provisos (Bits#(t, sz));        // t 需可存储（Reg#(Maybe#(t))）

    Reg#(Maybe#(t)) accumulator <- mkReg(tagged Invalid);
    Reg#(Bit#(TLog#(n))) received_cnt <- mkReg(0);

    // 收集阶段：从每个源取一个值并组合
    rule rl_collect if (received_cnt < fromInteger(valueOf(n)));
        let x <- sources[received_cnt].get();
        accumulator <= (isValid(accumulator)) ?
                        tagged Valid combine(validValue(accumulator), x) :
                        tagged Valid x;
        received_cnt <= received_cnt + 1;
    endrule

    // 输出阶段：所有值收集完毕，输出结果
    rule rl_output if (received_cnt == fromInteger(valueOf(n)));
        sink.put(validValue(accumulator));
        accumulator <= tagged Invalid;
        received_cnt <= 0;
    endrule

endmodule

// 组合归结器使用示例
/*
    场景1：求多个传感器的平均值

    function Int add(Int a, Int b) = a + b;

    Vector#(4, Get#(Int)) sensors <- replicateM(mkSensor);
    Put#(Int) avg_sink <- mkAverageSink;
```

### 组合器总结

上面的各种组合器示例的高级连接用法，实际上核心思想就是：仅处理拓扑关系，不处理数据处理逻辑，具体的数据逻辑在`CS/GP`模块中实现，权责分离

| 模式 | 解决的问题 | 核心机制 |
|:------:|:-----------:|:---------:|
| **仲裁器** | 多`→`一 访问冲突 | 轮询状态 + 请求/响应配对 |
| **路由器** | 一`→`多 地址解码 | 地址函数 + 设备索引 |
| **流水线** | 多级串联并行 | 流水线寄存器 + 阶段间 FIFO |
| **广播器** | 一`→`多 数据分发 | 循环遍历所有输出 |
| **归结器** | 多`→`一 数据聚合 | 轮询选择输入源 |

## 设计模式总结

实际上按照：`一`和`多`的笛卡尔组合，就可以得到所有的连接模式：

| 模式 | 接口 | 用途 |
|:------:|:------:|:------:|
| 点对点 | `Get` / `Put` | 简单数据流 |
| C/S | `Client` / `Server` | 事务交互 |
| 广播 | `Vector#(n, Put)` | 分发数据 |
| 收集 | `Vector#(n, Get)` | 聚合数据 |

而且推荐，使用的时候定义标准接口，且命名也直抒胸臆才好：

```bluespec
interface Cache;
  interface Server#(Req, Rsp) cpu_side;   // 处理器侧
  interface Client#(Req, Rsp) mem_side;   // 内存侧
endinterface
```
