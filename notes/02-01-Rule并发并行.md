# 规则的并发和并行

BSV采用一种别样的思路，另外一个视角的抽象，使用原子事务来描述电路逻辑

## 原子事务

```bluespec
rule r_swap;     // x y 旧值互换
    x <= y;      // 同时执行
    y <= x;      // 不需要临时变量
endrule
```

同一规则内写同一寄存器两次会直接编译报错，不同规则的规则间冲突使用调度注解来处理冲突

规则可以使用优先级，执行顺序等概念来消减冲突，保证原子性和可预见性

> 专有名词：
>
> CAN_FIRE  : 复合条件为真 = 显式守卫 ∧ 所调用全部方法的隐式条件（如 FIFO 的 notFull/notEmpty）
>
> WILL_FIRE : 在 CAN 的基础上，还满足调度的规则，被选中 <- 真正的实际执行

```bluespec
Reg#(int) x <- mkReg(0);

rule r1 (x < 10);   // CAN_FIRE 在 x<10 时为真
    x <= x + 1;
endrule

rule r2 (x > 5);    // CAN_FIRE 在 x>5 时为真
    x <= x + 2;
endrule

// 当 x 同时满足两个条件，两个规则的 CAN_FIRE 同时为真，它们都写 x，存在冲突
// 为了避免编译器默认乱选，需要手动来注解优先级，比如：
(* descending_urgency = "r1, r2" *)     // 当然，得写在规则前面，，，但为了上下文...
// 这样子在冲突的时候，就会优先执行 r1 而不选中 r2 因为他们随时随地冲突，所以只会执行其一
```

高级用法

```bluespec
Reg#(int) x <- mkReg(0);
Reg#(Bool) valid <- mkReg(False);

rule producer;
    x <= x + 1;
    valid <= True;
endrule

// 源码层没有 WILL_FIRE(...) 这种可调用构造（它只是生成的 Verilog 信号 WILL_FIRE_RL_*）
// 同周期内 producer 先于 consumer 的顺序由调度/共享状态(RWire/Wire)决定，而非在守卫里引用别的规则
rule consumer (valid);
    $display("Consuming: %d", x);
    valid <= False;
endrule
```

## 规则注解

BSV 的属性注解`(* ... *)`，写在紧随其后的**单个**规则/模块/方法/接口之前。

其中，常见的注解：

| 注解 | 语法 | 作用范围 | 说明 | 使用示例 |
|:------:|:------:|:----------:|:------:|:------:|
| `descending_urgency` | `"r1, r2, r3"` | 规则 | 指定优先级，左高右低 | `(* descending_urgency = "r_high, r_low" *)` |
| `preempts` | `"r1, r2"` | 规则 | r1 触发时强制禁用 r2 | `(* preempts = "r_int, r_norm" *)` |
| `mutually_exclusive` | `"r1, r2"` | 规则 | 声明规则互斥 | `(* mutually_exclusive = "rA, rB" *)` |
| `execution_order` | `"r1, r2"` | 规则 | 强制串行顺序 | `(* execution_order = "r_first, r_second" *)` |
| `synthesize` | - | 模块 | 生成独立 Verilog 模块/文件 | `(* synthesize *) module mkTop(...);` |
| `no_implicit_conditions` | - | 规则 | 断言无隐式条件（编译期【检查】，非移除） | `(* no_implicit_conditions *) rule r;` |
| `fire_when_enabled` | - | 规则 | 断言使能时必触发（编译期【检查】，不改硬件） | `(* fire_when_enabled *) rule r;` |
| `conflict_free` | `"r1, r2"` | 规则 | 断言两规则无冲突 | `(* conflict_free = "rA, rB" *)` |
| `always_ready` | - | 接口方法 | RDY 始终为真 | `(* always_ready *) method Action m;` |
| `always_enabled` | - | 接口方法 | EN 始终为真 | `(* always_enabled *) method Action m;` |
| `doc` | `"text"` | 模块/规则/方法 | 文档字符串 | `(* doc = "This module does X" *)` |
| `prefix` | `"str"` | 接口方法 | 方法端口名前缀 | `(* prefix = "my_" *)` |
| `ready` | `"sig"` | 接口方法 | 自定义 RDY 信号名 | `(* ready = "my_rdy" *)` |
| `enable` | `"sig"` | 接口方法 | 自定义 EN 信号名 | `(* enable = "my_en" *)` |
| `result` | `"sig"` | 接口方法 | 自定义返回值信号名 | `(* result = "my_result" *)` |
| `clock_prefix`/`reset_prefix`/`gate_prefix` | `"str"` | 模块 | 重命名生成的时钟/复位/门控端口 | `(* clock_prefix = "clk" *)` |
| `clock_family` | `"clk"` | 模块 | 时钟域归属 | `(* clock_family = "slow_clk" *)` |

单行使用方法：

```bluespec
// 应用于单个规则
(* descending_urgency = "r1, r2" *)
rule r1;
    x <= x + 1;
endrule

// 应用于模块
(* synthesize *)
module mkAdder(Empty);
    // ...
endmodule

// 应用于方法
interface FIFO_IFC;
    (* always_ready *)
    method Bit#(32) first();

    (* always_enabled *)
    method Action enq(Bit#(32) x);
endinterface
```

多条规则的调度关系：把规则名都列进同一个 `(* *)` 字符串，注解贴在**紧接其后的那一条**规则上（一条 `(* *)` 只挂在下一项上；要管多对关系就叠多行 `(* *)`）：

```bluespec
module mkMultiAnnotationExample(Empty);
    Reg#(int)   counter    <- mkReg(0);
    Reg#(int)   data       <- mkReg(0);
    Reg#(State) state      <- mkReg(IDLE);
    Reg#(Bool)  error_flag <- mkReg(False);

    // 多条调度关系，用多行 (* *) 叠加；每行的规则名都写在字符串里
    (* descending_urgency = "error_handler, reset_all, normal_op" *)  // 紧急度：左高右低
    (* preempts           = "reset_all, normal_op" *)                 // reset_all 触发则抢占 normal_op
    rule error_handler (error_flag);
        $display("ERROR: handling error");
        state <= ERROR_STATE; counter <= 0;
    endrule

    rule reset_all (state == RESET);
        state <= IDLE; counter <= 0; error_flag <= False;
    endrule

    (* mutually_exclusive = "normal_op, debug_rule" *)  // 声明两条互斥
    rule normal_op (state == ACTIVE);
        counter <= counter + 1;
        if (counter == 100) state <= IDLE;
    endrule

    rule debug_rule (state == DEBUG);
        $display("DEBUG mode");
    endrule

    // 完全独立的规则（无任何注解）
    rule independent (True);
        $display("independent: always runs");
    endrule
endmodule
```

> 关键：注解的作用对象永远是**它正下方的那一条**规则/模块/方法；规则间的关系靠**字符串里的名字列表**表达，而不是靠把多条规则“括进一个块”。
