# TLM 建模示例

<!-- lec05 续：把 04-01 的 GetPut/Client/Server/Connectable 串成一个完整可跑的事务级模型 -->

> TLM, Transaction-Level Modeling —— 事务级建模。核心一句话：
> **一笔"事务"（整个请求/响应结构体）经方法调用传递，而不在 pin 级逐线接。**
>
> BSV 里 TLM 的基石就是 base 库自带的 `GetPut` / `ClientServer` / `Connectable`（接口本身见 04-01）。
> 完整的 AMBA 总线级 TLM（TLMSend/Recv、TLMRequest/Response、burst…）在 **bsc-contrib** 的 `AMBA_TLM2/3`，见 16-01。

## 一个最小但完整的例子：CPU ↔ 内存

> 完整可跑工程：`execs/04-02-TlmMem`

### 事务类型（整个结构体就是"一笔事务"）

```bluespec
typedef struct { Bool write; Bit#(4) addr; Bit#(8) data; } MemReq  deriving (Bits, Eq);
typedef struct { Bit#(8) data; }                          MemResp deriving (Bits, Eq);
```

### 从设备 = `Server#(请求, 响应)`

```bluespec
module mkMem(Server#(MemReq, MemResp));
   Vector#(16, Reg#(Bit#(8))) mem <- replicateM(mkReg(0));
   FIFO#(MemResp) respQ <- mkFIFO;
   interface Put request;                 // 收请求
      method Action put(MemReq r);
         if (r.write) begin mem[r.addr] <= r.data; respQ.enq(MemResp{data:r.data}); end
         else                                       respQ.enq(MemResp{data:mem[r.addr]});
      endmethod
   endinterface
   interface Get response = toGet(respQ); // 发响应
endmodule
```

### 主设备 = `Client#(请求, 响应)`

```bluespec
module mkCpu(Client#(MemReq, MemResp));
   FIFO#(MemReq) reqQ <- mkFIFO;
   Reg#(Bit#(8)) got  <- mkReg(0);
   function Action issue(Bool w, Bit#(4) a, Bit#(8) d) = action
      reqQ.enq(MemReq{write:w, addr:a, data:d});
   endaction;

   // 用 mkFSM 而非 mkAutoFSM（见下方“坑”）
   FSM fsm <- mkFSM(seq
      issue(True, 3, 8'hAA); issue(True, 5, 8'hBB);   // 写
      issue(False, 3, 0);    issue(False, 5, 0);      // 读，应读回 AA/BB
   endseq);
   Reg#(Bool) started <- mkReg(False);
   rule go (!started); started <= True; fsm.start; endrule
   rule done (got == 4); $finish(0); endrule

   interface request = toGet(reqQ);       // 发请求
   interface Put response;                // 收响应
      method Action put(MemResp r); got <= got + 1; endmethod
   endinterface
endmodule
```

### 顶层：一行接通

```bluespec
(* synthesize *)
module mkTop(Empty);
   Client#(MemReq, MemResp) cpu <- mkCpu;
   Server#(MemReq, MemResp) mem <- mkMem;
   mkConnection(cpu, mem);   // client.request<->server.request、server.response<->client.response
endmodule
```

> `Client`/`Server` 的 `request`/`response` 配对（谁 `Get` 谁 `Put`）与 `toGet`/`toPut` 的定义见 04-01；
> 这里只把那套骨架填实成一个能跑的完整事务。`mkConnection` 能一行接通，正因 `Get`↔`Put`、`Client`↔`Server` 是可连接的对偶。

## 实测事务流

```
[CPU] --> WR addr=3 data=aa
[CPU] --> WR addr=5 data=bb
[CPU] <-- resp data=aa       # 写回执
[CPU] --> RD addr=3 data=0
[CPU] <-- resp data=bb
[CPU] --> RD addr=5 data=0
[CPU] <-- resp data=aa       # 读回 0xAA ✓
[CPU] <-- resp data=bb       # 读回 0xBB ✓
```

## 坑：`mkAutoFSM` 会过早 `$finish`

> 若主设备用 `mkAutoFSM` 跑请求序列，序列一结束它就 `$finish`，会**截断仍在路上的响应**（只看到前几笔 resp）。
> 解法：用 `mkFSM` + 手动 `start`，让真正的结束条件（如 `got == 4`）来收尾。
>
> 注：`mkFSM` 与 `mkAutoFSM` **都可综合**（FSM 逻辑都会编译成 Verilog，`make verilog` 可验证）；二者区别只在 `mkAutoFSM` 序列结束自动 `$finish` 这一【仿真】行为，与可综合性无关。

## 与"完整 TLM"的关系

- 本例是**手搓的事务级模型**，已具备 TLM 的全部要义：事务打包、请求/响应分离、Client/Server 对偶、一行互连。
- 工业级 **AMBA TLM**（bsc-contrib）在此之上加了标准总线语义：`TLMRequest`/`TLMResponse` 标准事务、突发传输、字节使能、`TLMSendIFC`/`TLMRecvIFC`、与 AXI/AHB/APB 的桥接等。详见 16-01。
