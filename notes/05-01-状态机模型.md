# 结构化状态机

<!-- lec06 -->

> StmtFSM, Structured Finite State Machine - 结构化有限状态机 - `import StmtFSM::*;`

传统的状态机是`每个状态一个规则`的手工状态机编码方式，容易出错，`SFSM`将抽象提升为类似软件编程的顺序、条件、循环描述方式

`SFSM`是描述状态机的语法糖，会被编译成规则，本质就是把一组行为"打包"，按照写的顺序自动执行

但是需要高性能并发，精细控制的场景，手写规则更合适

```bluespec
// 手写规则：你要手动管理"当前在第几步"
rule step1 (state == 0); ... state <= 1; endrule
rule step2 (state == 1); ... state <= 2; endrule
rule step3 (state == 2); ... state <= 3; endrule

// StmtFSM：你说"先做1，再做2，再做3"
seq
    动作1;
    动作2;
    动作3;
endseq
```

## 模型对比

**传统的状态机模型**：

```bluespec
typedef enum {
    S0, S1, S2, S3, S4
} State deriving (Bits, Eq);

module mkFSM_Manual(Empty);
  Reg#(State) state <- mkReg(S0);
  Reg#(int) counter <- mkReg(0);

  rule r0 (state == S0);
    $display("Step 0");
    state <= S1;
  endrule

  rule r1 (state == S1);
    $display("Step 1");
    state <= S2;
  endrule

  rule r2 (state == S2);
    $display("Step 2");
    if (counter < 5) begin
      counter <= counter + 1;
      state <= S1;  // 循环
    end else begin
      state <= S3;
    end
  endrule

  rule r3 (state == S3);
    $display("Done");
    $finish;
  endrule
endmodule
```

**结构化状态机模型**：

```bluespec
import StmtFSM::*;

// 编译器会自动把它转换成上面那4个规则。
// 不需要关心"状态"怎么管理，只需要关心"先做什么，后做什么"。
module mkFSM_StmtFSM(Empty);
  mkAutoFSM(
    seq
      $display("Step 0");
      $display("Step 1");
      for (i <= 0; i < 5; i <= i + 1)
        $display("Loop iteration %d", i);
      $display("Done");
      $finish;
    endseq
  );
endmodule
```

## 详细介绍

**基本块结构**：

```bluespec
seq ... endseq         // 顺序组合，原子执行
par ... endpar         // 分支并行，原子执行，全部结束才算结束
action ... endaction   // 原子动作单元

seq
  A;
  B;
  C;
endseq

// 与verilog的begin/end fork/join always块的区别就是bsv保障原子性
```

**块内语句示例**：

```bluespec
// if 判断
if (x > 10)
    r <= 233;
else action
    r <= 666;
endaction

// for 在 sfsm 内部可综合，毕竟是语法糖，这里 i 无论是寄存器还是编译常量均可综合
// 但是在外部，循环只有编译期已知的 for (integer i=5...) 可综合！i 是编译期常量
for (i <= 0; i < 5; i <= i + 1)  // i 得提前声明寄存器
    action
        // 每次迭代是一个时钟周期
        data_out <= data_in[i];
    endaction

// while 循环
while (!ready)
    action
        wait(1);  // 等待一个时钟周期，同样，作为语法糖才可被综合
    endaction

// repeat 循环
repeat (10)
    action
        $display("cycle");  // 注意：$display 仍不可综合，仅仿真用
        // 实际硬件操作
        count <= count + 1;
    endaction
```

**FSM接口方法**：

实例化后的状态机，外界可使用对应的接口，来了解状态机的运行状况以及一定程度上控制状态机

```bluespec
interface FSM;      // 没有参数直接省略了括号
    method Action start;           // 调用以启动状态机
    method Bool done;              // 是否完成？
    method Action waitTillDone;    // 等它完成
    method Action abort;           // 强制停止
    method Action reset();         // 重置（部分版本支持）
endinterface
```

**FSM创建与启动**：

```bluespec
FSM fsm <- mkFSM(stmt);  // 创建FSM，之后手动 fsm.start 来开始运行
mkAutoFSM(stmt);   // 自动开始+自动结束，创建就自动执行 self.start 直到结束
```

## 补充说明

```plaintext
1. 上面仨块可以根据目的和语义互相嵌套
2. auto_fsm 在测试的时候用的挺多，不过综合方面也可用
3. 自己定义好 stmt 将其视为 `宏` 就好，就像调用函数 ≈ 触发定义好的这组行为一样
```

其中，仨块互相嵌套的示例：

```bluespec
// A→(B、C→D 并行)→E
seq
    actionA;
    par
        actionB;
        seq
            actionC;
            actionD;
        endseq
    endpar;
    actionE;
endseq
```
