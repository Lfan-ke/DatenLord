# 与RTL互操作 - BVI

> BVI, Black Box Verilog Import - 是 BSV 中导入 RTL 模块的机制
> > 因为 bsc 直接只支持 Verilog 代码，所以其他的 HDL/HCL 都需要使用 Verilog 作为中转媒介，比如 VHDL 的导入需要 Verilog 包装器等等

**大致格式就是**：

```bluespec
import "BVI" <原始Verilog模块名> =
  module mk<BSV模块名> (<BSV接口类型>);

    // 时钟和复位（可选）
    default_clock <名称> (<Verilog时钟端口>);
    default_reset <名称> (<Verilog复位端口>);

    // 方法映射（关键字是 enable，不是 en；输出端口放在方法名【前】；没有 = (...) 右侧）
    method <BSV方法名> (<Verilog输入端口...>) enable (<使能端口>) ready (<就绪端口>);  // Action
    method <Verilog输出端口> <BSV方法名>;                                            // Value

    // 调度约束（告诉 BSV 编译器方法间的关系）
    schedule (<方法列表>) <约束类型> (<方法列表>);

  endmodule
```

## MAC 模块示例 Verilog 导入

```verilog
// mymac.v
module mymac(
    input        clk,
    input        rst_b,
    input        EN,
    input  [15:0] a,
    input  [15:0] b,
    input        clear,
    input  [15:0] clear_value,
    output [15:0] out
);
    reg [15:0] out;

    always @(posedge clk or negedge rst_b)
        if (!rst_b)
            out <= 16'd0;
        else if (clear)
            out <= clear_value;
        else if (EN)
            out <= out + a * b;
endmodule
```

其中，我们的 BVI 包装器：

```bluespec
// MacBVI.bsv
package MacBVI;

// 定义 BSV 接口 给上层使用
interface MacIFC;
    // 乘加操作：out <= out + a * b
    method Action acc(Int#(16) aa, Int#(16) bb);
    // 复位操作：out <= value
    method Action reset_acc(Int#(16) value);
    // 读取当前结果
    method Int#(16) read_y();
endinterface

// 导入 Verilog 模块，`import "BVI"` 后面加原始的 Verilog 模块名
import "BVI" mymac =
    module mkMac (MacIFC);

        // 时钟复位映射
        default_clock clk (clk);
        default_reset rst (rst_b);

        // acc 方法：参数映射到 Verilog 输入端口 a、b，使能端口 EN
        // 无 ready 子句 = 永远就绪（Verilog 模块没有 ready 输出）
        method acc(a, b) enable(EN);

        // reset_acc 方法：参数映射到 clear_value，使能端口 clear
        method reset_acc(clear_value) enable(clear);

        // read_y 值方法：输出端口 out 放在方法名前
        method out read_y;

        // ============================================================
        // 调度约束（告诉 BSV 编译器这些方法之间的关系）
        // ============================================================
        // read_y 必须在 reset_acc 之前（读旧值，写新值下周期才可见）
        schedule (read_y) SB (reset_acc);
        // read_y 必须在 acc 之前（读旧值）
        schedule (read_y) SB (acc);
        // acc 和 reset_acc 冲突（不能同时调用，会写同一个寄存器）
        schedule (acc) C (reset_acc);

    endmodule

endpackage

// 使用：`MacIFC mac <- mkMac;`
```

编译时指定 Verilog 文件目录：

```bash
# bsc 链接时查找 Verilog 的目录由 -vsearch 指定（`:` 分隔，`+` 代表默认路径）
# 默认原语在 $BLUESPECDIR/Verilog/
# 注意：-vsearch 重复给会被后者覆盖，要用单个 `:` 分隔串

bsc -verilog -vsearch +:./rtl:./ip -g mkTest Test.bsv
```

## FFT 模块示例 VHDL 导入

假设源文件：

```vhdl
-- my_fft.vhd
entity my_fft is
    port (
        clk     : in  std_logic;
        rst     : in  std_logic;
        start   : in  std_logic;
        data_in : in  std_logic_vector(15 downto 0);
        data_out: out std_logic_vector(31 downto 0);
        done    : out std_logic
    );
end entity;
```

创建包装器：

```verilog
// my_fft_wrapper.v
module my_fft_wrapper(
    input        clk,
    input        rst,
    input        start,
    input  [15:0] data_in,
    output [31:0] data_out,
    output        done
);
    // 实例化 VHDL 组件（工具会处理映射）
    my_fft u_my_fft (
        .clk(clk),
        .rst(rst),
        .start(start),
        .data_in(data_in),
        .data_out(data_out),
        .done(done)
    );
endmodule
```

之后就和上面一致了，其中，BVI 只找到 Verilog 这一层，到了 iverilog/vcs/quartus 这一步才会指定 VHDL 模块的路径，让它们读，而非 BSC 自己去读...

> 实际上 bsc 根本不"读"被导入的 RTL：`import "BVI"` 只是按你写的 method/schedule 约定，在生成的 Verilog 里**实例化**那个黑盒模块名。真正读 Verilog/VHDL 的是后端仿真/综合器。

## 方法 ↔ Verilog 端口映射（双向通用）

无论是 `import "BVI"`（把 Verilog 端口"认领"给方法）还是 `bsc -verilog` 导出（按规则生成端口），三类方法与端口的对应关系是一样的：

| BSV 方法 | 对应的 Verilog 端口 |
|:--:|:--:|
| `method Action m(x)` | `EN_m`(入,1) + `m_x`(入,参数) + `RDY_m`(出,1) |
| `method t m` (值方法) | `m`(出,返回值) + `RDY_m`(出,1) |
| `method ActionValue#(t) m(x)` | `EN_m`(入,1) + `m_x`(入) + `m`(出,返回值) + `RDY_m`(出,1) |

> 每个方法都有隐式条件，所以**都有 `RDY_`**；带副作用（Action/ActionValue）的才有 `EN_`。
> BVI 里若不写 `ready(...)` 子句即 `RDY` 恒真；不写 `enable(...)` 则该方法无使能（恒使能）。

## BVI 的时钟与复位

```bluespec
default_clock clk (CLK);            // 默认时钟，端口名 CLK
default_clock clk (CLK, CLK_GATE);  // 带门控输入
default_reset rst (RST_N);          // 默认复位
default_clock no_clock;             // 无时钟（纯组合 IP）—— 注意是这个写法
default_reset no_reset;             // 无复位
input_clock c2 (CLK2, CLK2_GATE) = clk2Expr;  // 额外输入时钟
input_reset  r2 (RSTN2)          = rst2Expr;  // 额外输入复位

// 指定某方法所属的时钟/复位域：
method foo(x) enable(EN) clocked_by(c2) reset_by(r2);
method bar(y) enable(EN) clocked_by(no_clock);   // 组合方法
```

> 易错点（很多网文/博客写错）：无时钟是 **`default_clock no_clock;`**，不是 `no_default_clock;`；
> 默认时钟是 `default_clock clk (CLK);`（有名字 `clk` 和端口 `CLK`），不是 `default_clock (CLK);`。

简易使用示例（带额外时钟域的 IP，其余 `...` 省略）：

```bluespec
import "BVI" dual_clk_ip =
   module mkDual #(Clock clk2, Reset rst2) (DualIfc);
      default_clock clk (CLK);
      default_reset rst (RST_N);
      input_clock  c2 (CLK2)  = clk2;        // 额外时钟由模块参数传入
      input_reset  r2 (RSTN2) = rst2;
      method push(D) enable(EN);                          // 默认时钟域方法
      method tick()  enable(TK) clocked_by(c2) reset_by(r2);   // c2 域方法
      ...
   endmodule
```

## 调度约束（schedule）速查

```bluespec
schedule (mA) CF (mB);   // conflict-free：同周期任意顺序都可并存
schedule (mA) SB (mB);   // sequenced-before：同周期可共存，逻辑上 mA 在 mB 之前
schedule (mA) C  (mB);   // conflict：同周期任何顺序都不能并存
schedule (mA) SBR (mB);  // SB 的"强制"变体（要求该顺序，反序即冲突）
schedule (m1, m2) CF (m3);   // 支持方法列表
```

> 寄存器式："读在写前" `schedule (read) SB (write)`；FIFO 式："enq/deq 冲突" `schedule (enq) C (deq)`。

简易使用示例（在 BVI 里声明方法关系，其余 `...` 省略）：

```bluespec
import "BVI" myfifo =
   module mkF (FIFOIfc);
      ...
      method enq(D) enable(EN_ENQ) ready(NOTFULL);
      method deq()  enable(EN_DEQ) ready(NOTEMPTY);
      method first  read(DOUT);
      schedule (first) CF (first);
      schedule (first) SB (deq);     // 先读后出队
      schedule (enq)   C  (deq);     // enq/deq 互斥
      ...
   endmodule
```

> 完整可跑的 BVI（含 enable/schedule）见 `execs/09-01-01-BviMac`。

## 反方向：BSV 导出为 Verilog

```bash
bsc -verilog -g mkMod -u MyMod.bsv   # 生成 mkMod.v；端口按上面的方法映射规则
```

控制导出端口的属性：

| 属性 | 位置 | 效果 |
|:--:|:--:|:--:|
| `(* always_ready *)` | 接口方法 | 去掉 `RDY_` 端口（断言恒就绪） |
| `(* always_enabled *)` | 接口 Action 方法 | 去掉 `EN_` 端口（须每周期被调用） |
| `(* clock_prefix="clk" *)` `(* reset_prefix="rst" *)` | 模块 | 重命名生成的时钟/复位端口 |
| `(* prefix="p_" *)` | 接口方法 | 该方法端口名前缀 |
| `(* result="out" *)` | 接口方法 | 自定义返回值端口名 |
| `(* ready="rdy" *)` `(* enable="en" *)` | 接口方法 | 自定义 RDY/EN 端口名 |

## 和 BH（Bluespec Classic）的关系

> BH（Bluespec Haskell / Classic，`.bs`）与 BSV（`.bsv`）是**同一个编译器 bsc** 的两种语法外壳，
> `import "BVI"` / `import "BDPI"` / `schedule` 这些互操作机制**完全一致**，只是写法不同，且两者可在同一工程混用。BH 语法详见 15-01 起。
