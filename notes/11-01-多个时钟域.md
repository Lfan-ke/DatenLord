## 杂七杂八

CPU/MMU/L1Cache等等的时钟与PCIe/UART/USB/RTC等等不一致。CPU可能较为高频2GHz左右，外设低频100MHz，而且外接的不同总线也会有不同的时钟要求，比如：TL接了CHI，又转接了AXI4，AXI4转接WB以及APB或者AHB等等多级总线架构等等。有些总线快，有些慢，同时还可能集成来自不同供应商的IP核，必要时为了节能还需要门控来关闭空闲模块时钟等。就需要不同的时钟来驱动。时钟多了就会乱，所以引入时钟域的概念。

> Clock clk1; - 特殊类型，不能与普通信号混用 - Bit#(1) x = clk1; -> 编译错误！

## 模块时钟

模块会默认隐含：一个默认时钟 外加 一个默认重置，但也可以选择完全无视，自己声明和使用自己创建的...

```bluespec
// Clock 是特殊类型，不能与普通信号混用
Clock clk1;           // 时钟信号
Bit#(1) x = clk1;     // ❌ 编译错误！不能赋值

// 隐式使用当前作用域默认的时钟和复位的寄存器
Reg#(Bit#(8)) cnt1 <- mkReg(0);

// 获取默认时钟和复位（显式）
Clock default_clk <- exposeCurrentClock();
Reset default_rst <- exposeCurrentReset();

// 显式使用默认时钟和复位
Reg#(Bit#(8)) cnt2 <- mkReg(0, clocked_by default_clk, reset_by default_rst);

// 比较时钟（编译时比较）  分支的内容也是编译时确定的
if (clk1 == clk2) begin
    // 编译时已知的相等性
end
```

**示例**：

```bluespec
module mkTop(Empty);
    // ==========================================
    // 当前模块拥有的时钟和复位：
    // 1. default_clock (隐式，始终存在)
    // 2. default_reset (隐式，始终存在)
    // 3. my_clk (显式创建)
    // 4. my_rst (显式创建)
    // ==========================================

    Clock default_clk <- exposeCurrentClock();
    Reset default_rst <- exposeCurrentReset();

    // mkAbsoluteClock(start, period)：参数① 起始延迟、② 周期（不是高/低电平宽度！）
    // 周期 20 → 高低各 10ns → 50MHz；起始延迟设 10
    Clock my_clk <- mkAbsoluteClock(10, 20);
    // 创建复位信号，必须指定时钟域
    Reset my_rst <- mkInitialReset(2, clocked_by my_clk);

    // 使用不同时钟的寄存器
    Reg#(Bit#(8)) reg_default <- mkReg(0);                                    // 隐式
    Reg#(Bit#(8)) reg_explicit <- mkReg(0, clocked_by default_clk, reset_by default_rst); // 显式
    Reg#(Bit#(8)) reg_my <- mkReg(0, clocked_by my_clk, reset_by my_rst);    // 自定义
    Reg#(Bit#(8)) reg_noreset <- mkReg(0, clocked_by my_clk, reset_by noReset); // 无复位
endmodule
```

**寄存器创建风格**：

```bluespec
// 风格1：最简 - 使用默认时钟和默认复位
Reg#(Bit#(8)) reg1 <- mkReg(0);

// 风格2：指定时钟 + noReset（无复位）
Reg#(Bit#(8)) reg2 <- mkReg(0, clocked_by src_clk, reset_by noReset);

// 风格3：指定时钟 + 显式复位
Reg#(Bit#(8)) reg3 <- mkReg(0, clocked_by src_clk, reset_by src_rst);

// 风格4：mkRegU - 未初始化（综合时节省资源）
Reg#(Bit#(8)) reg4 <- mkRegU(clocked_by src_clk, reset_by noReset);

// 风格5：mkRegA - 异步复位寄存器
Reg#(Bit#(8)) reg5 <- mkRegA(0, clocked_by src_clk, reset_by src_rst);

// 风格6：带初始值的寄存器
Reg#(Bit#(8)) reg6 <- mkReg(100, clocked_by src_clk, reset_by src_rst);
```

**获取对应表达式的时钟域**：

```bluespec
// clockOf() 返回表达式的时钟域
Clock c1 = clockOf(reg_style1);
Clock c2 = clockOf(src_counter + 3);

// 检查信号是否有有效时钟
Bool has_clock = clockOf(signal) != noClock;
```

## 时钟门控

> CG, Clock Gating
> > module mkGatedClock #(Bool v) (Clock clk_in, GatedClockIfc ifc);
>
> > 不需要时钟的时候，把时钟“关掉”，而不是让它空跑
>
> > 时钟不翻转 → 触发器不采样 → 动态功耗大大降低，硬件上通过一个 与门 或 锁存器+与门 实现
>
> > clk_gated = clk_in & gate_enable;

```bluespec
// 获取当前模块的默认时钟
Clock osc_clk <- exposeCurrentClock();

// 创建门控时钟
// mkGatedClock(init_cond, clock)  // init_cond 是门控【条件】寄存器的复位值（条件为真=时钟运行）
// init_cond = False: 复位后条件=0 → 时钟停止
// init_cond = True : 复位后条件=1 → 时钟运行
GatedClockIfc gc1 <- mkGatedClock(False, osc_clk);
Clock gated_clk1 = gc1.new_clk;  // 门控后的时钟（供子模块使用）

// 控制门控
rule update_gate;
    gc1.setGateCond(gate_on);   // True=运行时钟, False=停止时钟 - 动态控制门控条件
    Bool current_gate = gc1.getGateCond();  // 查询当前门控状态
endrule
```

**时钟族**：

> clock family
> > 属于同一族：它们最终来自同一起源，只是经过门控或分频
>
> > 同一族中的时钟之间 不需要同步器 就可以传递信号 属于编译时的避免跨域错误的编译手段

```bluespec
// 检查祖先关系
Bool is_anc = isAncestor(osc_clk, gated_clk1);

// 检查是否同一时钟族
Bool same_fam = sameFamily(osc_clk, gated_clk1);
```

## CDC 原语

> mkSyncReg, mkSyncFIFO, mkNullCrossingWire

### 寄存器（字）同步器

> mkSyncReg：握手脉冲协议字同步（非 2FF）

```bluespec
// 参数顺序: (initial_value, src_clock, src_reset, dst_clock)
Reg#(Bit#(8)) synced <- mkSyncReg(0, src_clk, src_rst, dst_clk);

// 写入同步寄存器（必须在 src_clk 域）
rule write_sync;
    synced <= src_counter;
endrule

// 读取同步寄存器（必须在 dst_clk 域）
rule read_sync;
    $display("synced=%0d", synced);
endrule
```

### FIFO 同步器

```bluespec
// 参数顺序: (depth, src_clock, src_reset, dst_clock)
SyncFIFOIfc#(Bit#(8)) fifo <- mkSyncFIFO(4, src_clk, src_rst, dst_clk);

// 生产者（src_clk 域）
rule producer (fifo.notFull);
    fifo.enq(data);
endrule

// 消费者（dst_clk 域）
rule consumer (fifo.notEmpty);
    let d = fifo.first;
    fifo.deq;
endrule
```

### 空同步器

```bluespec
// 参数顺序: (dst_clock, src_signal)
// 警告：不包含任何同步逻辑，仅用于无亚稳态风险的场合！
ReadOnly#(Bit#(8)) crossed <- mkNullCrossingWire(dst_clk, src_signal);

rule read_null;
    $display("unsafe value=%0d", crossed);
endrule
```

## 其他补充

**时钟信息**：

```
# 编译时显示时钟域分配
bsc -verilog \
    -keep-fires \                  # 保留 CAN_FIRE/WILL_FIRE 信号，便于分析规则触发
    -v \                           # 详细模式，输出编译过程信息
    -g mkTop \                     # 生成 mkTop 模块
    Top.bsv \                      # 源文件
    2>&1 | grep -E "clock|domain"  # 过滤只显示 clock 和 domain 相关行

...
```

| 选项 | 含义 |
|:------:|:------:|
| `-keep-fires` | 保留 CAN_FIRE/WILL_FIRE 信号，调试规则触发 |
| `-v` | 详细模式，输出编译过程 |
| `-show-schedule` | 显示调度顺序，含规则所在时钟域 |
| `-show-elab-progress` | 显示细化过程，追踪时钟域分配 |
| `2>&1` | 将 stderr 重定向到 stdout |
| `\| grep -E "clock\|domain"` | 过滤显示 clock 和 domain 相关行 |
| `tee compile.log` | 同时输出到终端和文件 |

> 补充：一般情况下，CAN/WILL会在编译的时候就优化消失掉，但是可以`-keep-fires`指定保留在生成的代码里，方便调试时看...
